# 归档

归档管理 API 与状态以 [`api/openapi.json`](../api/openapi.json) 为准。归档 ZIP 保存在 `ARCHIVE_DIR`，SQLite 数据库默认位于 `DATABASE_PATH`（容器中 `/config/pandaopds.db`）。数据库保存归档关联、元数据、进度和上游封面；ZIP 文件本身不会被搬入数据库。旧 `ARCHIVE_STATE_DIR` 中的 JSON 与 Bolt 文件仅用于首次幂等导入，导入后保留为备份，不再双写。

## 购买与下载

正常操作顺序是 **quote → 用户查看价格/大小/档位并决定 → start → 准备 → 下载**。报价不扣 GP、不创建任务。归档购买必须由用户明确发起；收藏同步与订阅抓取不会自动购买，除非用户单独启用自动下载。自动任务在调度前重新检查订阅授权、下载档位和删除抑制状态。

归档任务会持续记录在下载任务表中。提交结果不能确认时，任务进入 `needs_review`，服务不会盲目再次购买。只有确认上游尚未接受请求，任务才可作为普通失败处理。管理器状态 URL 可恢复的更新会在保留原 ZIP 的同时继续处理。

续传文件与 7z 转换临时文件位于 `CACHE_DIR/archive-staging/`。完成的 ZIP 在 `ARCHIVE_DIR` 中校验后发布，支持本地图片流阅读。图片缓存的容量淘汰不会清理归档。转换、发布和下载并发受 `ARCHIVE_DOWNLOAD_CONCURRENCY` 限制。

## 本地文件与迁移

归档书架以 `ARCHIVE_DIR` 中实际存在的 ZIP/CBZ 文件为准。启动只恢复 SQLite 状态并导入旧结构化 sidecar，不自动遍历归档目录或打开 ZIP。首次启动后的书架需要用户手动运行普通扫描；普通扫描只读取目录项与文件大小、修改时间，不打开归档内容、不计算哈希。新登记文件的页数显示为未知，打开 manifest 或第一页时才安全读取图片页并缓存页索引。列表与 OPDS summary 不会为未索引文件生成封面请求。

“深度检查”需要用户在网页确认，或显式运行 `pandaopds archive import --deep`。它会打开归档、读取图片页并计算完整容器 SHA-256，网络挂载目录可能产生较多网盘 I/O；它不是完整 ZIP CRC 校验。默认扫描不会哈希。归档相对路径是文档身份；同路径文件大小或修改时间变化时保留 ID、关联和进度，并清除页索引与缓存哈希。深度扫描只更新可选 SHA-256 和当前页索引，不按哈希差异切换身份；不同路径的文档不会自动合并进度。

扫描发现的 ZIP/CBZ 可包含 EH 作品或普通本地文档；未能证明 EH 身份的文件仍可阅读，但不会继承 EH 进度。文件被移除后会标为缺失；“删除文件”和清除缺失记录是不同操作。删除动作先持久记录精确文件指纹与抑制项，重启时只会验证和恢复该删除意图所列的文件；若文件内容已被替换则转入人工复核。

首次启动会在服务提供归档和自动下载前导入可识别的旧归档 JSON、封面、Bolt 进度和旧下载诊断，不打开 ZIP 内容。用户显式运行普通扫描后，服务会按旧 sidecar 保存的安全相对路径与唯一 EH 身份，把仍存在的普通文件和旧出版物元数据关联；旧文件大小、修改时间、哈希和归档状态不作为关联门槛，也不读取归档内容。关联阶段可重复执行，扫描结果显示有限的关联原因计数，不包含旧 sidecar 原文。手动关联或解除关联受保护；关联身份冲突时不自动选择或合并进度。没有旧本地阅读进度时可恢复旧 EH 阅读进度目标；已经存在本地进度时保留本地目标。完成初始元数据导入后，尚未扫描的本地文件不会出现在书架，用户可手动运行普通扫描。

首次打开时若挂载读取中断，不会保存部分页索引，也不会仅凭一次 I/O 错误将文档永久标为无效；再次点击阅读会显式重试。结构无效的文档也可通过再次点击阅读重新检查。文档 API 的读取错误会返回 `reason`、失败阶段、归档相对路径及已登记/当前文件签名；`mtime_ns` 使用十进制字符串，便于浏览器准确显示。归档相对路径是本地文档身份：普通扫描发现同一路径文件属性或内容变化时，会保留文档 ID、关联与阅读进度，清除旧页索引并在下次明确阅读时按当前文件重建。文件移除后仍能通过原 ID 读取恢复；不同路径的文档不会自动合并进度。修改时间只帮助判断页索引是否可复用，不作为拒绝打开文件的身份校验。

旧版手动命令仍可用于在服务停止时执行同一套导入与本地扫描，不再搬动 ZIP 或写回 sidecar：

```sh
docker compose stop pandaopds
docker compose run --rm pandaopds archive import
docker compose run --rm pandaopds archive import --deep
docker compose up -d
```

数据库与 `ARCHIVE_DIR` 都应使用持久卷。备份需同时保存 SQLite 数据库（使用 SQLite 在线备份能力或停服复制）和归档 ZIP；旧 sidecar 可作为迁移审计备份保留。

## 合成数据验证记录

2026-11-20 在本机用 2,000 和 5,000 个合成归档做了启动、查询与恢复检查。每个 fixture ZIP 仅含一张 32×48 PNG，压缩后约 243 B；测试使用预热的本机文件系统缓存，不代表真实大文件扫描 I/O 或生产数据。结果显示 SQLite 查询有改善，但正常启动仍较旧实现慢，尤其在 5,000 条时；这次迁移不宣称所有操作都更快。

| 合成归档数 | 启动旧版 / SQLite | 归档列表中位数旧版 / SQLite | 进度历史中位数旧版 / SQLite | 进程堆旧版 / SQLite |
|---:|---:|---:|---:|---:|
| 2,000 | 0.607 / 0.691 秒 | 92.3 / 28.7 毫秒 | 4.14 / 1.97 毫秒 | 9.38 / 11.14 MB |
| 5,000 | 0.875 / 3.534 秒 | 178.6 / 39.8 毫秒 | 8.49 / 4.95 毫秒 | 18.95 / 20.56 MB |

2,000 条数据库一致性备份约 5.66 MB、87.8 ms；5,000 条约 13.70 MB、225 ms。备份包含 SQLite 元数据和缓存封面，不包含 `ARCHIVE_DIR` 中的 ZIP。将 2,000 条数据库备份还原到隔离目录（不带旧 JSON/Bolt），服务正常启动并保留 2,000 条 EH 关联。该演练使用合成 fixture；没有读取或迁移真实部署的 `/config` 或归档，也没有执行任何购买操作。上述启动性能数字来自本改造采用轻量目录扫描前的合成基线，不代表新的无扫描启动与显式深度检查性能。

## 版本更新

新版 ZIP 下载、校验和发布成功后，书架关联切换到新版本；旧文件的删除有持久意图和指纹校验。报价和更新必须由用户明确确认最高 GP 花费。订阅自动下载默认关闭，显式启用后可能消耗 GP。提交结果不明确且没有可恢复状态 URL 时，原版本保持可用并暂停该次任务等待核实。
