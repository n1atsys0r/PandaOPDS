# SQLite 重构与订阅／归档解耦方案

日期：2026-11-19。状态：设计草案，供后续实施使用；本文描述目标行为，不代表当前已实现。

## 1. 目标与已确认边界

本方案承接 SQLite 统一持久化方向，同时调整归档和收藏同步的业务边界。不要先按旧的「收藏即归档记录」模型完成数据库迁移，再重复改造。

- **探索**：实时访问上游，搜索、浏览出版物。
- **订阅**：定期执行预设来源或自定义搜索，将发现的出版物元数据缓存到本地，供稍后检视；可按显式开启的规则自动下载。
- **归档**：管理 `ARCHIVE_DIR` 内实际存在的受支持文件，注册本地文档并可选关联 EH 图库；接受非 EH 文档。
- **下载任务**：独立管理排队、下载、失败和恢复，不以无文件的归档记录承载任务状态。

SQLite 固定放在 `/config`，建议文件名为 `/config/pandaopds.db`。统一保存业务状态、图库元数据、订阅、进度、版本关系和上游封面；ZIP 与可重建的阅读图片／生成封面缓存继续放文件系统。TOML 文本配置保持现状。

保持现有 ZIP 目录和相对路径，不主动搬动、改名或重新打包。本文中的 `/archive` 指用户所述归档根目录，实际路径始终由 `ARCHIVE_DIR` 决定；当前 Docker 默认值为 `/data/archives`，不因本次改造变更。

本期的「类似 RSS」指持久化订阅、周期抓取和稍后检视体验，不包含通用 RSS/Atom 抓取器，也不等于完整内容离线缓存。

## 2. 现状与需要解除的耦合

当前 Go 实现存在以下关系：

- `internal/favorites/sync.go` 扫描收藏后调用 `Archive.Store.Catalog`，即使没有 ZIP，也创建 `unarchived` 状态和元数据 sidecar。
- `internal/app/archive_api.go` 将归档列表与收藏状态混合，前端在归档内同时展示未下载、下载任务和本地文件。
- `internal/archive/scanner.go` 以旧 sidecar 为入口，发现的是带状态的书架，不是完整的本地文件集合。
- `internal/progression` 使用 BoltDB；归档使用 JSON、内存映射和 `index.snapshot`，收藏另用 JSON。
- 前端的探索／出版物展示位于 `frontend/src/components/OpdsHome.vue`；归档及相关操作大量集中在 `App.vue`、`state.js`。

目标是让多个模块共用 SQLite，但各自拥有明确的数据和写入职责。共用数据库不意味着订阅可以直接修改本地文档状态。

## 3. 业务对象与身份

| 对象 | 身份与职责 | 不承担的职责 |
| --- | --- | --- |
| 出版物 | 内部 `publication_id`；EH 来源使用 `(provider, gid, token)` 唯一约束；保留列表／详情元数据与来源 | 不因被收藏或订阅发现就宣称存在本地文件 |
| 作品／版本组 | 稳定 `work_id`，关联各出版物版本、EH 别名和当前选用版本 | 不以当前下载任务状态替代文件有效性 |
| 本地文档 | 稳定 `document_id`、归档相对路径、格式、文件事实和校验状态；可选关联出版物 | 不要求有 EH 身份；不保存收藏成员关系 |
| 订阅 | 来源、固定抓取条件、调度、基线与自动下载规则 | 不直接创建归档记录或改变远端收藏 |
| 订阅条目 | 订阅与出版物的成员关系、首次／最近发现时间、已检视／隐藏状态 | 不等于已下载；不同订阅各自维护检视状态 |
| 下载任务 | 手动或自动下载意图、来源、质量、执行状态与结果文档 | 下载开始不等于归档已存在 |

关系约束：

- 一个出版物可出现在多个订阅中，也可关联多个本地文件；一份本地文档首期最多关联一个明确的出版物版本。
- 本地文档无需关联出版物即可展示、下载和本地阅读。不为非 EH 文件伪造 gid/token。
- EH 身份关联与文件重复判断分别处理：同一 EH 版本的多个文件不自动合并或删除。
- EH 版本组继承现有版本归并语义；本地文件绑定实际版本，旧链接由兼容层解析，不盲目将旧文件映射成最新内容。

## 4. 归档：以文件为事实来源

### 4.1 扫描与注册

扫描从 `ARCHIVE_DIR` 的文件枚举开始，不要求 `state.json` 或 `gallery.json` 存在。首期支持 ZIP，以及通过同一 ZIP 阅读链路验证的 `.cbz`；不顺带扩展 RAR、7z、PDF。格式按内容校验，不能只依赖扩展名。普通无可读图片的 ZIP 作为诊断项报告，不进入可阅读书架。

忽略下载／发布临时文件及非普通文件，默认不跟随符号链接。相对路径必须限制在归档根目录内；扫描不解压全部内容，也不执行网络查询或购买。复用当前读取链路的图片过滤与自然排序，明确资源上限，避免对异常压缩包无界展开。

注册流程：枚举文件 → 读取基本属性 → 检查容器与可读页面 → 收集可用元数据及身份线索 → 分批写入 SQLite。文件 I/O 不在长数据库事务内执行；登记前复核属性，跳过仍在变化的文件。

同一路径、未变化文件的重复扫描应幂等。大小与修改时间只用于减少检查，不能证明内容相同；需要内容指纹时按需后台计算。发现移动文件时，仅有足够可靠且无歧义的证据才保留原 `document_id`，否则作为待确认关联，不凭同名或同大小迁移进度。相同内容的多个路径也不自动删除。

### 4.2 EH 关联证据

| 证据 | 默认处理 |
| --- | --- |
| 本服务成功下载任务与发布日志记录 | 校验对应文件后自动关联 |
| 旧 sidecar 中完整 gid/token 与明确 payload 路径 | 无冲突且文件校验通过后关联，记录迁移来源 |
| 压缩包内元数据携带完整 EH URL／身份 | 作为显式身份声明保存来源；无冲突时可关联，但不宣称已在线验证或内容完全匹配 |
| 用户手动指定 EH URL／版本 | 记录为人工关联；后续允许解除或修正 |
| 文件名中的 gid、标题或模糊匹配 | 仅提供候选，不自动认定身份 |

冲突不得覆盖已有人工关联，也不触发付费动作。来源与证据级别需可追溯；本地资料无法证明 EH 身份时保持未关联。

### 4.3 文件状态、缺失与删除

本地文档状态区分 `available`、`missing`、`invalid`，另记扫描错误；EH 身份是否关联是独立维度。正常归档列表只展示已确认存在的文档，无文件的旧记录仅进入诊断／历史视图。

扫描须有 run ID、完成范围和完成标记。只有完整成功覆盖的目录范围才能将未见文件标记缺失；取消、权限错误、目录不可访问均不得推断删除。访问时也检查文件可用性，避免将数据库标记当成永久存在的证明。

- 删除本地文件不取消收藏、不取消订阅、不删除出版物和进度；文件删除成功后更新状态，失败则保留记录并返回错误。
- 文件外部消失后保留缺失记录、关联和进度供恢复，默认不再进入普通归档与离线 OPDS。
- 「清除缺失记录」与「删除实际文件」是不同操作。
- 用户主动删除归档后记录自动下载抑制，避免下一轮订阅立即重下；只有明确重新下载／解除抑制才恢复。
- 原有「收藏条目删除 ZIP 后回退 unarchived」废止；订阅条目继续存在，归档内不再保留无文件卡片。

## 5. 订阅：持久化发现与检视

### 5.1 来源与查询

首期提供 EH 收藏、预设搜索和自定义关键词搜索适配器；预设搜索使用现有受支持的搜索能力，不包含任意远端 URL。收藏来源支持全部收藏，分类作用域与自动下载筛选分别记录，以承接旧行为。

订阅保存独立、可复现的查询条件：关键词、分类、排序和必要筛选。创建时可以从探索条件复制，但不能随 `home.toml`、探索胶囊或全局筛选后续修改而静默变化。订阅页面内临时筛选只查询本地结果，不扩大或改变抓取范围。

编辑来源或实质性抓取条件会产生新 revision，并重新建立基线；不把条件修改后的全部匹配结果当作新内容自动下载。暂停后恢复不重置已有身份去重与基线。

### 5.2 周期抓取与结果提交

周期、手动刷新、收藏写操作触发的刷新走同一调度入口；同一订阅单飞行，全部订阅共用上游限流、重试和熔断。任务保留抓取时间、分页数、结果数、错误、是否完整等诊断。

首次抓取是有页数／数量限制的基线，不承诺抓取无限历史。抓取条件与排序确定每类来源的停止策略：收藏复用现有不透明游标与已知阈值，搜索不能直接照搬收藏阈值。使用重叠扫描和身份去重减少排序漂移的影响，并标明抓取窗口，不宣称绝对无遗漏。

每页结果、成员关系和可恢复检查点以短事务提交；游标不保证长期有效时，下次从头重叠抓取并去重。区分「完成用户声明的有限抓取窗口」与「触及单轮保护上限导致尚未完成窗口」；后者、网络中断、凭据失效分别记录，不能当作完整同步。完成搜索窗口也不代表完成全部远端结果对账。

基线只有完成其声明的窗口后才标记完成；失败／截断待补齐期间不自动下载，基线首次发现的条目也不得在恢复后重新解释为新条目。新订阅及新 revision 的首次发现默认只缓存，不自动下载存量。用户若需下载存量，通过显式批量操作执行。

条目消失不代表应删除：搜索订阅保留历史发现结果；收藏来源只有在确认完整对账完成或明确移除收藏成功后，才能标记已不在远端收藏。部分抓取不得移除成员关系；历史结果仍可检视，默认视图可筛选当前收藏。

### 5.3 检视与缓存边界

订阅列表完全从 SQLite 读取；打开页面、分页、筛选和标记已检视均不触发上游列表抓取。显示最近成功抓取时间、进行中状态和错误。「立即抓取」是明确动作，返回后重新读取本地结果。

默认按首次发现时间倒序，以条目 ID 作稳定次序；元数据更新不使旧条目重新变成未检视。已检视状态与阅读进度分开，隐藏与远端取消收藏分开。

缓存对象是出版物列表元数据与逐步取得的上游封面；封面沿用懒加载，未取得的封面使用占位，不阻塞条目保存。不默认下载全部详情、评论或正文图片；打开详情和在线阅读仍可能联网。首期不自动淘汰订阅历史，提供显式清理已检视／隐藏条目的能力，并保留防重复下载所需的最小记录。

## 6. 自动下载与独立任务

自动下载按订阅显式开启，新建订阅默认关闭；规则包含类别范围、质量和新发现范围，界面明确可能消耗 GP。旧收藏自动归档的已开启状态和分类规则迁移保留，不把已有授权扩大至其他订阅。未知收藏分类继续按原实现兼容，并在规则说明中明确。

处理链路：抓取结果 → 条目提交 → 确定性策略检查 → 持久化下载意图 → 下载执行 → 校验并发布文件 → 注册本地文档及关联。

- 发现条目与持久化下载意图应在同一事务内完成，或通过持久化待处理标记保证可恢复，不能仅依赖内存通知。
- 同一出版物版本、目标质量及兼容的文件结果跨订阅去重；合并任务保留所有来源，已有有效文件不重复购买。
- 全局任务并发控制、已有归档质量升级和版本切换策略沿用现有行为；更高质量请求只有在较低质量文件可安全保留时执行。
- 任务状态建议为 `queued/running/succeeded/failed/canceled/needs_review`，阶段另记报价、购买、传输和发布；只有成功关联实际文件才是下载完成。
- 自动失败不反复重试付费动作；购买响应不明或购买后中断时先恢复／核实已有结果，不能承诺跨上游与本地事务的 exactly-once，也不能盲目再次购买。
- 取消订阅阻止尚未开始的自动任务；合并任务仍被其他订阅或手动请求需要时不连带取消。运行中任务是否取消由用户明确操作，不静默中断已付款传输。
- 下载完成前只出现在订阅的任务状态或独立下载面板，不进入归档文档列表。

ZIP 发布继续采用同卷临时文件和可恢复发布日志：校验 → 记录发布意图 → 发布最终路径 → 事务注册文档／完成任务 → 清理旧文件。重启根据日志与文件事实补齐步骤；不能用 SQLite 事务替代文件恢复。扫描与下载共享发布约定，避开半成品并通过唯一路径约束处理同时登记。

## 7. 前端组织与客户端兼容

导航保留「探索」「归档」，新增「订阅」。归档中的收藏同步入口、无文件浏览和下载失败卡片迁出；收藏写操作仍可从探索、订阅和关联 EH 的归档文档发起。

订阅复用探索中**出版物模式**的卡片网格、封面、标题／标签展示、响应式行为、详情入口和筛选交互。实现时抽取共享展示组件和数据适配层，不直接复用探索的实时抓取状态，不要求订阅支持分组导航模式。局部模块拆分以本次复用为边界，不扩展为整个 `App.vue` 重写。

订阅特有界面包括订阅选择与配置、未检视／全部／隐藏、最近抓取状态、自动下载设置，以及下载状态标记。归档状态从关联的本地文档派生，不能复制一个永久的 `is_archived` 布尔值。多订阅合并视图按出版物去重，只有所有可见成员都已检视才视作已检视；标记动作明确作用于当前视图覆盖的成员。

归档以本地文档为操作单位，支持已关联／未关联筛选、缺失诊断、扫描、关联修正和本地阅读。下载任务面板可由订阅和归档入口打开，但不能混充归档书目。

OPDS 与阅读链路必须同步支持本地文档身份：

- `/opds/v1.2`、`/opds/v2.0` 与 PSE 页码约定保持；归档 feed 只输出实际可读本地文档，非 EH 文档使用稳定本地标识和本地内容链接。
- 现有 gid/token 路径保留为兼容入口，解析到已关联的文件与现有版本选择规则；新增 document ID 路径承载非 EH 文档和同一图库的多份文件。
- 本地文档在无 EH 凭据或断网时仍可阅读；关联到 EH 不代表阅读时必须请求 EH。
- 进度采用明确的目标类型和身份：保留现有 EH 作品进度行为，非 EH 文档按 `document_id` 保存。以后补做 EH 关联不自动覆盖两边已有进度；冲突需显式处理，保留原记录。
- 订阅 OPDS feed 不作为首期必须项；既有实时收藏 OPDS 入口保持语义，不擅自改为订阅快照。

## 8. SQLite 模型与模块职责

以下为概念表，不是最终 DDL；精确 API schema 仍以实施时更新的 OpenAPI 为准。

| 表／表组 | 核心内容 |
| --- | --- |
| `publications`、`works`、版本关系与别名表 | 来源身份、版本关系、结构化查询字段、完整元数据 JSON 与来源完整度 |
| `documents`、文档关联证据 | 独立 ID、唯一归档相对路径、文件属性、状态、可选出版物关联与证据 |
| `subscriptions`、`subscription_revisions` | 来源与固定条件、调度、暂停、自动下载规则、基线 |
| `subscription_items`、抓取 runs／检查点 | 唯一 `(subscription_id, publication_id)`、发现／检视状态、抓取覆盖与恢复信息 |
| 收藏来源成员信息 | 当前收藏分类、成员有效性及对账信息，不等同于任意搜索订阅成员 |
| `download_jobs`、任务来源／发布日志 | 阶段、质量、来源、错误、去重、发布恢复与自动下载抑制 |
| `progressions` | 目标类型／身份、原有冲突时间语义、设备、引用、快照及保护／淘汰规则 |
| `covers` | 上游原始封面 BLOB、MIME、校验值、所属出版物版本和来源 |
| schema／导入版本记录、维护状态 | 表结构迁移与旧数据导入进度、扫描结果、清理状态 |

不要把所有资料强拆成列，也不要将全部状态原样塞入 JSON 后继续全量扫描。常用过滤、分页和关联字段结构化，其余元数据保留 JSON；低完整度列表信息不能覆盖已有详情或人工字段。索引按实际查询建立，采用稳定排序，明确深分页和总数统计成本。

模块建议：

- `internal/storage`：SQLite 生命周期、连接与事务、schema 迁移、导入工具；纯 Go 驱动，保持无 CGO 构建。PRAGMA 对实际连接生效，定义写入串行化、忙等待、checkpoint 和关机顺序。
- 出版物／目录仓储：公共元数据、来源身份与版本关系，供探索、订阅和文档关联复用。
- `internal/subscription`：抓取适配器、调度、检视状态、规则和下载意图。
- `internal/favorites`：保留 EH 收藏读写与来源适配能力，移除对归档建档的依赖。
- `internal/archive`：本地文档扫描、验证、注册、文件访问及发布恢复；现有下载管理可渐进拆分为任务服务，不要求一次改动所有包名。
- `internal/progression`：替换 BoltDB，保留现有 EH 行为并增加本地目标。将任意 Go predicate 查询改为明确查询条件，才能把筛选分页下推 SQL。
- `internal/app` 与前端：协调 API 与展示，不再跨模块拼接并维护另一套持久化状态。

## 9. 旧数据迁移与配置兼容

首次升级先迁移并校验，完成前不启动抓取、自动下载和写请求。旧文件保持只读备份，不逐个改名作为唯一完成证据；使用导入版本、幂等键和可恢复检查点。迁移故障不得触发购买或删除 ZIP。

| 旧数据 | 目标与处理 |
| --- | --- |
| 有实际有效 ZIP 的 state/gallery | 导入出版物、版本关系，按实际路径注册文档；旧封面原字节导入 SQLite |
| `unarchived` 收藏记录 | 导入出版物和收藏订阅成员，不创建文档 |
| 无 ZIP 的非收藏旧元数据 | 保留为出版物历史资料，不自动创建订阅，也不放入正常归档 |
| 下载中／失败状态 | 导入任务与恢复信息；失败不自动重购；中断任务按阶段恢复或待确认 |
| `favorites_sync.json` | 创建一个内置「EH 收藏」订阅，保留 known、分类、baseline、错误和自动下载规则 |
| BoltDB 进度、快照、别名、保护信息 | 完整迁移并校验，不能只导入百分比；缺失文件不导致进度丢失 |
| 未被 sidecar 覆盖的文件 | 文件扫描独立发现；无法确认身份时注册未关联文档 |

收藏旧 known 中只有身份、缺少展示资料的条目也保留占位和基线身份，后续抓取补齐，不解释为新发现。迁移数据库导入完成与归档盘扫描完成分别记录；扫描完成前暂停自动下载，避免尚未登记的旧文件被重复购买。自动下载前仍需检查实际目标文件。

旧 `FAVORITES_SYNC_*` 作为过渡配置：首次导入用于生成内置收藏订阅，之后 SQLite 中的订阅配置为权威，环境变量不在每次启动时覆盖用户修改。原周期值为 0 时继续关闭周期、保留手动及收藏写操作触发；原自动归档 false 不能迁移成 true。首次导入后的旧配置忽略行为应有明确启动提示与迁移文档。全局限流和下载质量等服务配置继续按现有配置来源生效。

旧收藏 API 写操作保留，成功后触发收藏订阅刷新；旧同步状态／手动运行入口在过渡期代理到内置收藏订阅。归档列表不再返回无文件条目属于明确的语义变更，需更新 OpenAPI、前端和变更说明，不能用兼容层偷偷保留旧混合列表。

导入期间需要 BoltDB 读取能力，不能一边要求自动迁移一边立即移除 bbolt。首期保留其仅用于迁移；后续若移除依赖，应另提供迁移工具或宣布支持版本边界。

SQLite 使用一致性备份方式，运行时不把简单复制 `.db` 当作备份流程。保留迁移前副本只支持回到迁移前状态，不保证旧版本能读取升级后的新增数据；ZIP 不在元数据备份内，需分别备份。

## 10. 实施顺序与交付边界

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1：模型与契约 | 固化身份、状态、删除及订阅基线语义；设计文档 ID 阅读契约与兼容路径 | 核心行为和旧字段映射完整，不照搬原方案的单一 archives 表 |
| 2：存储与迁移 | SQLite、仓储、进度迁移、旧数据导入与只读校验报告 | 可中断重跑，旧数据保留，自动任务尚未启用 |
| 3：本地归档 | 文件扫描、非 EH 文档、本地阅读／进度／OPDS、任务与发布恢复 | 无文件不进归档，旧 ZIP 不搬动，扫描不会误删 |
| 4：订阅后端 | 收藏与关键词适配器、基线／调度、成员状态、自动下载去重与抑制 | 收藏不再调用 Catalog，付费中断不会盲目重试 |
| 5：界面与切换 | 共享出版物布局、订阅页、归档简化、下载面板、配置与 API 文档 | 三种入口语义一致，旧入口兼容与新身份阅读可用 |
| 6：升级验收 | 真实旧数据演练、故障恢复、跨平台静态构建和性能对比 | 全部必需测试通过后切换，旧 JSON 不再双写 |

阶段是可审查实现单元，不代表应向用户发布只完成数据库替换、仍保留旧业务耦合的中间版本。每个已迁移领域只保留一个权威写入口；最终切换前可使用隔离数据副本演练，不让旧后台任务并发写入源数据。

实施分工建议：根代理负责模型、公共契约、迁移和付费恢复边界；一个实现代理承担当前阶段的实现、测试与修复闭环。阶段间复用上下文，不按前端／后端强行拆出相互等待的并行工作。

## 11. 验收标准

### 行为与回归

- 收藏同步只增加订阅结果，不增加归档文档；探索仍为实时浏览，订阅分页／筛选只读本地数据。
- 无 sidecar、无 EH 身份的有效图片 ZIP 可注册、展示、离线阅读并保存进度；非图片、损坏、临时文件不混入可读书架。
- 同一 EH 版本多文件可区分；重复扫描不增加重复记录；移动、同名替换、关联冲突不误转进度。
- 无凭据／断网时已存在本地文档仍可阅读；PSE 页码、旧链接、EH 进度冲突／别名／淘汰规则保持。
- 订阅首次基线、条件 revision、恢复后补抓、分页截断不意外触发存量下载；关键词来源不误用收藏游标策略。
- 多订阅命中同一出版物只产生所需的下载任务；隐藏／取消收藏不删除本地文件；主动删除文件后不被自动重下。
- 旧收藏自动下载授权和分类范围不扩大，迁移与重启不触发重复购买。

### 故障与迁移

- 在分页提交、迁移分批、下载购买、ZIP 发布、数据库注册和旧文件清理处模拟中断，验证幂等恢复及不确定付费结果处理。
- 模拟数据库锁冲突、磁盘写满、取消扫描、部分目录错误；不把扫描失败解释为文件全体缺失。
- 比对迁移前后条目、字段、进度、版本关系和封面校验值；恢复备份验证上游封面可在断网时读取。
- 原文件与未知字段不静默丢弃；迁移旧封面不依赖重新下载，也不要求重新下载 ZIP。

### 检查与性能

实施阶段执行受影响 Go 测试、`go test ./...`、`CGO_ENABLED=0 go build ./cmd/pandaopds`、前端 `npm test` 与 `npm run build`，并验证 linux/amd64、linux/arm64 构建及 OpenAPI 与实际响应一致。

用同一份具有代表性的数据比较迁移前后的正常启动、首次迁移、归档扫描、历史／订阅列表延迟和内存；覆盖数千条及更大规模，并区分冷／热缓存。不预先承诺 O(1) 启动或毫秒级结果，数据库打开、恢复与文件扫描分开计时。封面统计实际数量和大小，验证数据库备份／恢复耗时可接受。

本方案仅修改设计文档；上述构建、测试、故障演练和性能检查均为后续实施要求，尚未执行。
